Erklärung

Vorwissen: L10 – Stetige Verteilungen, insbesondere der zentrale Grenzwertsatz, auf dem dieses ganze Kapitel ruht, und L4 für Mittelwert und Standardabweichung. Hier beginnt die schliessende Statistik, die in L13 fortgesetzt wird.

Die Kennzahl ist selbst zufällig

Bisher beschrieben Kennzahlen die vorliegenden Daten. Interessant ist aber selten die Stichprobe, sondern das, woraus sie stammt. Aus dreissig gemessenen Werkstücken soll etwas über die gesamte Produktion folgen.

Der entscheidende Gedankenschritt: Eine zweite Stichprobe hätte einen anderen Mittelwert ergeben. Der berechnete Wert ist damit selbst eine Zufallsgrösse, und die Frage lautet, wie stark er von Stichprobe zu Stichprobe schwankt.

Das lässt sich simulieren, weil wir die Grundgesamtheit hier kennen:

  • R
  • Python
# Grundgesamtheit: Erwartungswert 500, Standardabweichung 40
mittelwerte <- replicate(2000, mean(rnorm(30, mean = 500, sd = 40)))

ggplot(data.frame(mittelwerte), aes(mittelwerte)) +
  geom_histogram(bins = 40, fill = "grey75", colour = "white") +
  geom_vline(xintercept = 500, linewidth = 0.8) +
  labs(x = "Mittelwert einer Stichprobe (n = 30)", y = "Anzahl")
mittelwerte = rng.normal(500, 40, size=(2000, 30)).mean(axis=1)

fig, ax = plt.subplots(figsize=(7, 3.2))
ax.hist(mittelwerte, bins=40, color="0.75", edgecolor="white")
ax.axvline(500, color="black")
ax.set_xlabel("Mittelwert einer Stichprobe (n = 30)")
ax.set_ylabel("Anzahl")
plt.show()

Diese Verteilung heisst Stichprobenverteilung. Sie liegt um den wahren Wert herum, und ihre Streuung ist die Grösse, um die es geht.

Standardfehler ist nicht Standardabweichung

Der Unterschied wird ständig verwechselt und ist zentral.

Grösse beschreibt die Streuung von hängt ab von
Standardabweichung \(s\) den Einzelwerten der Grundgesamtheit
Standardfehler \(s/\sqrt{n}\) dem geschätzten Mittelwert zusätzlich vom Stichprobenumfang 
stichprobe <- rnorm(30, mean = 500, sd = 40)

c(streuung_einzelwerte = sd(stichprobe),
  standardfehler       = sd(stichprobe) / sqrt(length(stichprobe)),
  simuliert            = sd(mittelwerte)) |> round(2)
streuung_einzelwerte       standardfehler            simuliert 
               38.81                 7.09                 7.47

Der berechnete Standardfehler und die tatsächlich simulierte Streuung der Mittelwerte stimmen überein. Das ist der Beleg dafür, dass die Formel das Richtige tut.

Die Wurzel im Nenner hat eine unangenehme Folge: Genauigkeit wird teuer. Wer den Standardfehler halbieren will, braucht die vierfache Stichprobe.

n <- c(10, 40, 160, 640)
data.frame(n, standardfehler = round(40 / sqrt(n), 2))
    n standardfehler
1  10          12.65
2  40           6.32
3 160           3.16
4 640           1.58

Vom Punkt zum Intervall

Ein einzelner Wert sagt nichts über seine Genauigkeit. Das Konfidenzintervall gibt stattdessen eine Spanne an, gebildet als Schätzwert plus minus ein Vielfaches des Standardfehlers.

Bei unbekannter Varianz, also praktisch immer, wird nicht mit der Normalverteilung gerechnet, sondern mit der t-Verteilung. Sie hat schwerere Ränder und liefert dadurch etwas breitere und damit ehrlichere Intervalle. Mit wachsendem Umfang verschwindet der Unterschied:

n <- c(5, 10, 30, 100, 1000)
data.frame(
  n,
  t_quantil      = round(qt(0.975, df = n - 1), 3),
  normal_quantil = round(qnorm(0.975), 3)
)
     n t_quantil normal_quantil
1    5     2.776           1.96
2   10     2.262           1.96
3   30     2.045           1.96
4  100     1.984           1.96
5 1000     1.962           1.96

Der bekannte Faktor 1.96 ist der Grenzwert. Bei fünf Beobachtungen liegt der richtige Faktor bei 2.78, also deutlich darüber.

  • R
  • Python
x <- round(rnorm(25, mean = 12.2, sd = 0.8), 2)

t.test(x, conf.level = 0.95)$conf.int
[1] 11.76157 12.31603
attr(,"conf.level")
[1] 0.95
# von Hand, damit sichtbar ist, was passiert
se <- sd(x) / sqrt(length(x))
mean(x) + c(-1, 1) * qt(0.975, df = length(x) - 1) * se
[1] 11.76157 12.31603
x = np.round(rng.normal(12.2, 0.8, 25), 2)
se = x.std(ddof=1) / np.sqrt(len(x))

print(stats.t.interval(0.95, df=len(x) - 1, loc=x.mean(), scale=se))
(np.float64(11.770197758332097), np.float64(12.445002241667902))

Was das Intervall bedeutet, und was nicht

Hier liegt die häufigste Fehlinterpretation der ganzen Statistik. Die Aussage bezieht sich auf das Verfahren, nicht auf das einzelne berechnete Intervall. Der wahre Parameter ist fest, das Intervall ist zufällig.

Richtig ist: Wendet man das Verfahren immer wieder an, überdecken 95 Prozent der so erzeugten Intervalle den wahren Wert. Falsch ist die Aussage, der Parameter liege mit 95 Prozent Wahrscheinlichkeit in diesem einen Bereich.

Das lässt sich zeigen:

wahr <- 500
proben <- replicate(100, rnorm(25, mean = wahr, sd = 40), simplify = FALSE)

intervalle <- do.call(rbind, lapply(seq_along(proben), function(i) {
  ki <- t.test(proben[[i]])$conf.int
  data.frame(lauf = i, unten = ki[1], oben = ki[2])
}))
intervalle$trifft <- intervalle$unten <= wahr & intervalle$oben >= wahr

ggplot(intervalle, aes(lauf, ymin = unten, ymax = oben, colour = trifft)) +
  geom_linerange(linewidth = 0.5) +
  geom_hline(yintercept = wahr, linewidth = 0.7) +
  scale_colour_manual(values = c("TRUE" = "grey70", "FALSE" = "black")) +
  labs(x = "Wiederholung", y = "Konfidenzintervall", colour = "überdeckt") +
  theme(legend.position = "bottom")

sum(!intervalle$trifft)     # wie viele verfehlen den wahren Wert
[1] 5

Von hundert Intervallen verfehlen einige den wahren Wert, und zwar ungefähr fünf. Welches davon betroffen ist, weiss man in der Praxis nie, weil der wahre Wert unbekannt ist. Genau deshalb ist die Aussage über das Verfahren und nicht über das Einzelintervall formuliert.

Anteilswerte

Für Anteile gilt dieselbe Logik mit einem eigenen Standardfehler. Die einfache Näherung wird bei sehr kleinen oder sehr grossen Anteilen unbrauchbar, weil das Intervall dann über null oder eins hinausragen kann.

  • R
  • Python
treffer <- 42; versuche <- 200

prop.test(treffer, versuche)$conf.int    # mit Stetigkeitskorrektur
[1] 0.1570714 0.2743361
attr(,"conf.level")
[1] 0.95
binom.test(treffer, versuche)$conf.int   # exakt
[1] 0.1557398 0.2730687
attr(,"conf.level")
[1] 0.95
# der problematische Fall: sehr kleiner Anteil
prop.test(1, 40)$conf.int
[1] 0.001306388 0.147342139
attr(,"conf.level")
[1] 0.95
print(proportion_confint(42, 200, alpha=0.05, method="wilson"))
(0.15928412069978998, 0.2716461685990246)
print(proportion_confint(42, 200, alpha=0.05, method="beta"))    # exakt
(0.15573975672412832, 0.27306870461379884)
print(proportion_confint(1, 40, alpha=0.05, method="normal"))    # laeuft ins Negative
(0.0, 0.07338273420199073)

Die letzte Zeile zeigt das Problem. Ein Intervall, dessen untere Grenze negativ ist, kann für einen Anteil nicht stimmen. Verfahren wie Wilson oder das exakte nach Clopper-Pearson vermeiden das.

Warum wird ein Konfidenzintervall breiter, wenn man von 95 auf 99 Prozent Niveau geht?

Weil Sicherheit mit Unschärfe bezahlt wird
Richtig. Ein höheres Niveau verlangt, dass das Verfahren häufiger richtig liegt. Das geht nur, indem mehr Werte zugelassen werden. Bei hundert Prozent wäre das Intervall unendlich breit und wertlos.
Weil die Stichprobe kleiner wird
Der Umfang bleibt unverändert, nur der Faktor vor dem Standardfehler wächst.
Weil die Streuung der Daten zunimmt
Die Daten sind dieselben.

Eine Umfrage berichtet 52 Prozent Zustimmung mit einem Intervall von 49 bis 55 Prozent. Was folgt für die Frage, ob die Mehrheit zustimmt?

Die Mehrheit stimmt zu, der Punktwert liegt über 50
Der Punktwert allein trägt diese Aussage nicht, und genau dafür steht das Intervall daneben.
Die Frage bleibt offen
Richtig. Das Intervall enthält Werte unter fünfzig Prozent, also ist auch eine Minderheit mit den Daten vereinbar.
Die Mehrheit stimmt nicht zu
Ebenso wenig belegt. Beide Möglichkeiten liegen im Intervall.

In Abbildung 3 sind hundert Konfidenzintervalle gezeichnet, einige verfehlen den wahren Wert. Was zeigt das Bild?

Dass das Verfahren fehlerhaft ist
Die Fehlschläge sind eingebaut und ihre Häufigkeit ist genau das gewählte Niveau.
Dass die Aussage dem Verfahren gilt und nicht dem einzelnen Intervall
Richtig. Rund fünf von hundert verfehlen den wahren Wert. Welches betroffen ist, weiss man in der Praxis nie, weil der wahre Wert unbekannt ist.
Dass die Stichproben zu klein waren
Bei grösseren Stichproben wären die Intervalle schmaler, aber immer noch würden rund fünf Prozent danebenliegen.
