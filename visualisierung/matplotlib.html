Figure und Axes, Achsen, Beschriftung und Export in Python.

Diese Seite ist ein Entwurf. Der Inhalt steht, ist aber noch nicht durchgeprüft.

Kernideen

  • Figure als Leinwand, Axes als Koordinatensystem
  • Objektorientiertes Interface gegenüber pyplot
  • Grundtypen: Linie, Streuung, Balken, Histogramm
  • Mehrere Teilgrafiken mit subplots
  • Beschriftung, Achsen, Legende, Export

Erklärung

Vorwissen: NumPy und SciPy und pandas, weil die Daten von dort kommen. Wer ggplot2 kennt, hat den Vergleich zu ggplot2 im Kopf; der Unterschied im Denkansatz ist der rote Faden dieser Seite.

Zwei Bedienweisen, und warum das verwirrt

Matplotlib lässt sich auf zwei Arten bedienen, und Codebeispiele im Netz mischen beide. Wer den Unterschied nicht kennt, kopiert Zeilen zusammen, die nicht zusammenpassen.

Der pyplot-Weg arbeitet auf einer impliziten aktuellen Grafik. Jeder Befehl wirkt auf das, was zuletzt angelegt wurde:

plt.figure(figsize=(7, 2.8))
plt.scatter(maschinen["laufzeit"], maschinen["verbrauch"], s=10, alpha=0.6)
plt.xlabel("Laufzeit (h)")
plt.ylabel("Verbrauch (l)")
plt.show()

Der objektorientierte Weg erzeugt Figure und Axes ausdrücklich und ruft alles darauf auf:

fig, ax = plt.subplots(figsize=(7, 2.8))
ax.scatter(maschinen["laufzeit"], maschinen["verbrauch"], s=10, alpha=0.6)
ax.set_xlabel("Laufzeit (h)")
ax.set_ylabel("Verbrauch (l)")
plt.show()

Empfehlung ohne Ausnahme, sobald mehr als eine Grafik im Spiel ist: der objektorientierte Weg. Nur so bleibt eindeutig, in welches Koordinatensystem gezeichnet wird, und nur so lassen sich Grafiken in Funktionen erzeugen und zurückgeben.

Die Begriffe

Begriff was es ist
Figure das ganze Bild, samt Grösse und Auflösung
Axes ein einzelnes Koordinatensystem darin
Axis eine Achse, also x oder y

Die Verwechslung von Axes und Axis ist eingebaut und lässt sich nur merken: Ein Axes ist die Zeichenfläche, kein Strich.

fig, achsen = plt.subplots(2, 2, figsize=(7, 4))
print(type(fig).__name__)
Figure
print(achsen.shape)              # ein Gitter aus vier Axes
(2, 2)
plt.close(fig)                   # hier nur zur Anschauung, nicht zeichnen

subplots liefert beides in einem Schritt und ist deshalb der übliche Einstieg.

Mehrere Teilgrafiken

typen = ["Fräse", "Presse", "Drehbank"]

fig, achsen = plt.subplots(1, 3, figsize=(7, 3.2), sharey=True)
for ax, t in zip(achsen, typen):
    teil = maschinen[maschinen["typ"] == t]
    ax.scatter(teil["laufzeit"], teil["verbrauch"], s=12, alpha=0.7, color="0.3")
    ax.set_title(t)
    ax.set_xlabel("Laufzeit (h)")
achsen[0].set_ylabel("Verbrauch (l)")
fig.tight_layout()
plt.show()

sharey=True sorgt für die gemeinsame Skala und ist genau das, was Facetten in ggplot2 automatisch tun. tight_layout verhindert, dass sich Beschriftungen überlappen.

Der Unterschied im Denkansatz

Hier liegt der eigentliche Kontrast zu ggplot2. Dort beschreibt man, welche Variable auf welche visuelle Eigenschaft abgebildet wird, und die Grafik entsteht daraus. Matplotlib kennt keine solche Grammatik; jedes Element wird einzeln gezeichnet.

Am deutlichsten wird das beim Einfärben nach Gruppen. ggplot2 braucht dafür ein Wort, Matplotlib eine Schleife:

  • R
  • Python
ggplot(maschinen, aes(laufzeit, verbrauch, colour = typ)) +
  geom_point(alpha = 0.7, size = 1.5) +
  labs(x = "Laufzeit (h)", y = "Verbrauch (l)", colour = "Typ")
fig, ax = plt.subplots(figsize=(7, 3.2))
for t in ["Fräse", "Presse", "Drehbank"]:
    teil = maschinen[maschinen["typ"] == t]
    ax.scatter(teil["laufzeit"], teil["verbrauch"], s=15, alpha=0.7, label=t)

ax.set_xlabel("Laufzeit (h)")
ax.set_ylabel("Verbrauch (l)")
ax.legend(title="Typ")
plt.show()

Der Preis ist mehr Code für den Standardfall. Der Gewinn ist volle Kontrolle, wenn eine Abbildung genau so aussehen muss wie verlangt, etwa mit einer zweiten y-Achse, eingezeichneten Anmerkungen oder ungewöhnlichem Layout.

Beschriftung und Anmerkung

Eine Grafik ohne Achsenbeschriftung ist unfertig. Der Titel sollte die Aussage tragen, nicht den Diagrammtyp wiederholen.

fig, ax = plt.subplots()

for t in ["Fräse", "Presse", "Drehbank"]:
    teil = maschinen[maschinen["typ"] == t]
    ax.scatter(teil["laufzeit"], teil["verbrauch"], s=15, alpha=0.7, label=t)

# Ausgleichsgerade ueber alle Punkte
k = np.polyfit(maschinen["laufzeit"], maschinen["verbrauch"], 1)
xs = np.linspace(maschinen["laufzeit"].min(), maschinen["laufzeit"].max(), 2)
ax.plot(xs, np.polyval(k, xs), color="black", linewidth=1, linestyle="--")

ax.annotate("Presse liegt durchgehend höher",
            xy=(18, 8 + 2.4 * 18 + 14), xytext=(6, 85),
            arrowprops={"arrowstyle": "->", "color": "black"}, fontsize=9)

ax.set_title("Der Verbrauch steigt linear mit der Laufzeit")
ax.set_xlabel("Laufzeit (h)")
ax.set_ylabel("Verbrauch (l)")
ax.legend(title="Typ", loc="upper left")
plt.show()

Solche Anmerkungen sind der Fall, in dem sich der niedrigere Abstraktionsgrad auszahlt: Position, Pfeil und Text lassen sich frei setzen. Abbildung 6 zeigt, wie weit eine Grafik damit kommt, ohne dass ein weiteres Paket nötig wäre.

Export

fig.savefig("abbildung.pdf", bbox_inches="tight")     # Vektor, fuer Druck
fig.savefig("abbildung.png", dpi=300, bbox_inches="tight")

Vektorformat, wo es geht, denn es bleibt bei jeder Vergrösserung scharf. Wo es Raster sein muss, mindestens 300 dpi. bbox_inches="tight" schneidet den überflüssigen Rand ab, der sonst besonders bei Achsenbeschriftungen entsteht.

Pandas bringt eine eigene plot-Methode mit, die intern Matplotlib nutzt. Für den schnellen Blick während der Exploration reicht sie; sie gibt ein Axes-Objekt zurück, auf dem sich anschliessend weiterarbeiten lässt.

ax = maschinen.plot.scatter(x="laufzeit", y="verbrauch", s=8,
                            alpha=0.6, figsize=(7, 3), color="0.3")
ax.set_xlabel("Laufzeit (h)")
ax.set_ylabel("Verbrauch (l)")
plt.show()

Warum ist der objektorientierte Weg bei mehreren Teilgrafiken zwingend, wie in Abbildung 3?

pyplot wirkt immer auf die zuletzt angelegte Grafik
Richtig. Bei mehreren Teilbildern ist von aussen nicht mehr erkennbar, welches gerade das aktuelle ist, und die Reihenfolge der Befehle entscheidet über das Ergebnis. Mit ausdrücklichen Axes-Objekten steht in jeder Zeile, wohin gezeichnet wird.
pyplot kann nur eine Grafik pro Dokument erzeugen
Es kann beliebig viele, nur nicht eindeutig angesprochen werden.
Der objektorientierte Weg ist schneller
Die Laufzeit ist dieselbe, der Gewinn liegt in der Eindeutigkeit.

Was ist der Unterschied zwischen Axes und Axis?

Axes ist die Zeichenfläche, Axis eine einzelne Achse darin
Richtig. Ein Axes enthält zwei Axis-Objekte. Die Namensähnlichkeit ist die häufigste Verwirrung beim Lesen der Dokumentation.
Axes ist die Mehrzahl von Axis und meint dasselbe
Sprachlich ja, in Matplotlib aber sind es zwei verschiedene Dinge.
Axis ist das ganze Bild, Axes ein Ausschnitt
Das ganze Bild ist die Figure.

Typische Aufgaben

Grundgerüst mit einer Achse

fig, ax = plt.subplots(figsize=(7, 4.2))
ax.plot(x, y)
ax.set_xlabel("Zeit")
ax.set_ylabel("Wert")
ax.set_title("Verlauf")

Mehrere Teilgrafiken nebeneinander

fig, axes = plt.subplots(1, 2, sharey=True)
axes[0].hist(werte)
axes[1].boxplot(werte)

Häufige Diagrammtypen

ax.scatter(x, y, s=12, alpha=0.7)    # Streudiagramm
ax.bar(kategorien, hoehen)           # Balken
ax.hist(werte, bins=20)              # Histogramm
ax.boxplot([gruppe_a, gruppe_b])     # Boxplots nebeneinander

Eine Stelle im Diagramm beschriften

ax.annotate("Ausreisser", xy=(x0, y0), xytext=(x0 + 1, y0 + 5),
            arrowprops={"arrowstyle": "->"})

Achsenbereich, Gitter und Legende

ax.set_xlim(0, 100)
ax.grid(True, alpha=0.3)
ax.legend(loc="upper left", frameon=False)

Speichern in Druckqualität

fig.savefig("abbildung.png", dpi=300, bbox_inches="tight")
fig.savefig("abbildung.pdf", bbox_inches="tight")   # vektoriell
