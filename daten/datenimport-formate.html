Datenimport und Formate

Data Wrangling
R
Python
CSV, Excel, JSON und Pickle lesen und schreiben, Kodierung beachten.

Diese Seite ist ein Entwurf. Der Inhalt steht, ist aber noch nicht durchgeprüft.

Kernideen

  • Der erste Blick nach dem Import gehört den Spaltentypen
  • Trennzeichen, Dezimaltrennzeichen und Kodierung sind explizit anzugeben
  • Datumsangaben werden beim Import umgewandelt, nicht später
  • Text, der Zahl sein sollte, verrät fast immer ein Problem in den Rohdaten
  • Jedes Format hat seinen Zweck: CSV zum Austausch, Parquet für Grösse, JSON für Verschachtelung

Erklärung

Vorwissen: R-Grundlagen oder pandas. Was danach kommt, ist die Prüfung auf Datenqualität und das Umformen im Data Wrangling.

Import: der erste Blick gehört den Spaltentypen

Der häufigste Importfehler im deutschsprachigen Raum ist das Dezimalkomma. Werkzeuge gehen vom angelsächsischen Format aus, die Datei kommt aber mit Semikolon als Trennzeichen und Komma als Dezimalzeichen. Das Ergebnis sieht auf den ersten Blick brauchbar aus und ist es nicht.

Die folgende Datei entsteht im Chunk selbst, damit das Beispiel ohne Fremddatei nachvollziehbar bleibt:

  • R
  • Python
inhalt <- c("datum;typ;verbrauch",
            "01.03.2026;A;12,4",
            "02.03.2026;B;9,8",
            "03.03.2026;A;14,1")

pfad <- tempfile(fileext = ".csv")
writeLines(inhalt, pfad)

# Standardannahme: Komma trennt Spalten. Passt hier nicht.
falsch <- read_csv(pfad, show_col_types = FALSE)
ncol(falsch)          # alles in einer einzigen Spalte

# read_csv2 erwartet Semikolon als Trenn- und Komma als Dezimalzeichen
richtig <- read_csv2(pfad, show_col_types = FALSE)

Entscheidend ist, dass verbrauch erst mit der richtigen Einstellung numerisch wird. Ohne sie bliebe die Spalte Text, und jede spätere Rechnung würde entweder abbrechen oder, schlimmer, stillschweigend etwas Falsches liefern.

Die Spalte datum ist auch jetzt noch Text. Datumsangaben im europäischen Format erkennt kein Import von selbst:

  • R
  • Python
mit_datum <- richtig |>
  mutate(datum = dmy(datum))        # Tag-Monat-Jahr
str(mit_datum)
tibble [3 × 3] (S3: tbl_df/tbl/data.frame)
 $ datum    : Date[1:3], format: "2026-03-01" "2026-03-02" ...
 $ typ      : chr [1:3] "A" "B" "A"
 $ verbrauch: num [1:3] 12.4 9.8 14.1
richtig["datum"] = pd.to_datetime(richtig["datum"], format="%d.%m.%Y")
print(richtig.dtypes)
datum        datetime64[us]
typ                     str
verbrauch           float64
dtype: object

Warum das wichtig ist, zeigt ein Sortierversuch. Als Text stünde der 1. März vor dem 2. Februar, weil verglichen wird, was vorne steht. Als Datum stimmt die Reihenfolge, und Differenzen zwischen zwei Zeitpunkten lassen sich überhaupt erst rechnen.

Eine Spalte kommt beim Import als Text an, obwohl nur Zahlen darin stehen. Das Dezimalzeichen ist bereits richtig eingestellt. Was ist die nächstliegende Ursache?

Ein einzelner Platzhalter für fehlende Werte, etwa ein Strich
Richtig. Ein einziger solcher Eintrag genügt, weil der Vektor nur einen Typ tragen kann. Dasselbe gilt für Tausendertrennung oder angehängte Einheiten.
Die Datei ist zu gross
Die Grösse beeinflusst den erkannten Typ nicht.
R kann Zahlen nur aus Excel-Dateien lesen
Der Import aus Text funktioniert, er muss nur richtig eingestellt sein.

Warum sollte das Datum direkt beim Import umgewandelt werden und nicht erst kurz vor der Grafik?

Weil die Umwandlung später länger dauert
Die Rechenzeit ist nicht das Problem.
Weil jeder Schritt dazwischen sonst mit Text arbeitet und falsch sortiert oder gruppiert
Richtig. Wer nach Monat gruppiert, bevor das Datum ein Datum ist, gruppiert nach Zeichenketten und merkt es erst am Ergebnis.
Weil ggplot2 keine Datumsangaben darstellen kann
Kann es sehr wohl, sofern der Typ stimmt.

Typische Aufgaben

CSV mit europäischen Konventionen lesen

  • R
  • Python
readr::read_delim("daten.csv", delim = ";", locale = readr::locale(decimal_mark = ","))
pd.read_csv("daten.csv", sep=";", decimal=",", encoding="utf-8")

Spaltentypen selbst festlegen statt raten lassen

  • R
  • Python
readr::read_csv("daten.csv", col_types = readr::cols(
  id = readr::col_integer(),
  datum = readr::col_date(format = "%d.%m.%Y"),
  wert = readr::col_double()
))
pd.read_csv("daten.csv", dtype={"id": "Int64", "wert": "float64"},
            parse_dates=["datum"], dayfirst=True)

Excel, JSON und Parquet

  • R
  • Python
readxl::read_excel("mappe.xlsx", sheet = "Daten", skip = 2)
jsonlite::fromJSON("antwort.json")
arrow::read_parquet("gross.parquet")
pd.read_excel("mappe.xlsx", sheet_name="Daten", skiprows=2)
pd.read_json("antwort.json")
pd.read_parquet("gross.parquet")

Nur einen Teil einlesen, um die Struktur zu prüfen

  • R
  • Python
readr::read_csv("gross.csv", n_max = 1000)
pd.read_csv("gross.csv", nrows=1000)

Schreiben

  • R
  • Python
readr::write_csv(df, "ergebnis.csv")
saveRDS(df, "ergebnis.rds")
df.to_csv("ergebnis.csv", index=False)
df.to_parquet("ergebnis.parquet")

CSV verliert die Typinformation, RDS und Parquet behalten sie. Für Zwischenstände einer Auswertung ist das der wichtigere Punkt als die Dateigrösse.
