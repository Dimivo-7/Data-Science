Datenbankzugriff aus R und Python

Datenbanken
SQL
R
Python
DBI und RSQLite, sqlite3 und SQLAlchemy im praktischen Einsatz.

Diese Seite ist ein Entwurf. Der Inhalt steht, ist aber noch nicht durchgeprüft.

Kernideen

  • Verbindung aufbauen, Abfrage senden, Ergebnis als Data Frame entgegennehmen
  • Parameter statt zusammengebauter Zeichenketten, sonst droht SQL-Injektion
  • Verbindungen gehören geschlossen, am besten im Kontextmanager
  • SQLite als Datei ohne Server, MySQL und PostgreSQL mit Server
  • Aggregieren gehört in die Datenbank, nicht in den Arbeitsspeicher

Erklärung

Vorwissen: SQL für die Abfragen selbst und Datenmodellierung für den Aufbau der Tabellen.

Zugriff aus beiden Sprachen

  • R
  • Python
ergebnis <- dbGetQuery(con, "
  SELECT a.kategorie, SUM(b.betrag) AS umsatz
  FROM bestellung b JOIN artikel a ON a.artikel_id = b.artikel_id
  GROUP BY a.kategorie")

str(ergebnis)      # ein gewoehnlicher Data Frame
'data.frame':   3 obs. of  2 variables:
 $ kategorie: chr  "Elektronik" "Mechanik" "Pneumatik"
 $ umsatz   : num  2400 740 1968
df = pd.read_sql_query("""
  SELECT a.kategorie, SUM(b.betrag) AS umsatz
  FROM bestellung b JOIN artikel a ON a.artikel_id = b.artikel_id
  GROUP BY a.kategorie
""", verbindung)

print(df)
    kategorie  umsatz
0  Elektronik  2400.0
1    Mechanik   740.0
2   Pneumatik  1968.0
print(df.dtypes)
kategorie        str
umsatz       float64
dtype: object

Das Ergebnis ist in beiden Fällen die vertraute Tabelle, mit der weitergearbeitet wird wie mit jedem anderen Data Frame.

Wieviel gehört in die Datenbank, wieviel in die Auswertung? Meine Regel: Filtern und Aggregieren möglichst früh in SQL, damit nur die benötigte Datenmenge über die Leitung geht. Modellierung, Grafik und alles Iterative danach in R oder Python. Eine Million Zeilen zu laden, um daraus fünf Gruppensummen zu bilden, ist die häufigste vermeidbare Wartezeit.

Parameter statt Zeichenkettenbau

Eine Abfrage aus Nutzereingaben zusammenzukleben ist die klassische Sicherheitslücke und erzeugt ausserdem Fehler bei Anführungszeichen. Beide Sprachen bieten Platzhalter:

  • R
  • Python
dbGetQuery(con,
  "SELECT bezeichnung FROM artikel WHERE kategorie = ?",
  params = list("Mechanik"))
     bezeichnung
1 Kugellager 608
2      Dichtring
print(pd.read_sql_query(
    "SELECT bezeichnung FROM artikel WHERE kategorie = ?",
    verbindung, params=("Mechanik",)))
      bezeichnung
0  Kugellager 608
1       Dichtring

SQLite oder MySQL

SQLite braucht keinen Server und liegt als einzelne Datei vor, oder wie hier nur im Arbeitsspeicher. Zum Üben, für Zwischenstände und für kleine Projekte ist es ideal. MySQL und PostgreSQL sind der Serverfall mit Nutzerverwaltung, gleichzeitigen Zugriffen und Rechtevergabe. Die SQL-Grundlagen sind dieselben, die Unterschiede liegen in Datentypen und Erweiterungen.

Typische Aufgaben

Verbinden, abfragen, schliessen

  • R
  • Python
con <- DBI::dbConnect(RSQLite::SQLite(), "laden.sqlite")
df <- DBI::dbGetQuery(con, "SELECT * FROM artikel")
DBI::dbDisconnect(con)
import sqlite3
import pandas as pd

with sqlite3.connect("laden.sqlite") as verbindung:
    df = pd.read_sql_query("SELECT * FROM artikel", verbindung)

Werte als Parameter übergeben

  • R
  • Python
DBI::dbGetQuery(con, "SELECT * FROM artikel WHERE preis > ?", params = list(100))
pd.read_sql_query("SELECT * FROM artikel WHERE preis > ?", verbindung, params=(100,))

Zeichenketten selbst zusammenzubauen ist die Ursache von SQL-Injektion und zusätzlich fehleranfällig bei Anführungszeichen und Datumsformaten.

Einen Data Frame in eine Tabelle schreiben

  • R
  • Python
DBI::dbWriteTable(con, "ergebnis", df, overwrite = TRUE)
df.to_sql("ergebnis", verbindung, if_exists="replace", index=False)

Nachsehen, was in der Datenbank liegt

  • R
  • Python
DBI::dbListTables(con)
DBI::dbListFields(con, "artikel")
pd.read_sql_query("SELECT name FROM sqlite_master WHERE type = 'table'", verbindung)

Grosse Tabellen in Portionen lesen

for teil in pd.read_sql_query("SELECT * FROM bestellung", verbindung, chunksize=10_000):
    verarbeite(teil)

Besser noch: aggregieren lassen, wo die Daten liegen, und nur das Ergebnis holen. Eine Datenbank ist darin schneller als jede Schleife im Arbeitsspeicher.

Verbindung zu einem Server statt zu einer Datei

from sqlalchemy import create_engine
motor = create_engine("postgresql+psycopg://benutzer:passwort@host:5432/datenbank")
df = pd.read_sql_query("SELECT * FROM artikel", motor)
